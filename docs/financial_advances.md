# توثيق إجراءات العهدة المالية

## 1. قاعدة البيانات

### جدول `advances` (العُهد)
**الملف:** `supabase/migrations/20240101000001_advances.sql`

| الحقل | النوع | الوصف |
|--------|-------|-------|
| `id` | integer (identity) | المعرّف الفريد للعهدة |
| `driver_id` | integer (FK → drivers.id) | السائق المستفيد |
| `amount_given` | numeric (default 0) | المبلغ الكامل المسلم للسائق |
| `date_out` | text (YYYY-MM-DD) | تاريخ تسليم العهدة / انطلاق الرحلة |
| `status` | text (default 'pending') | الحالة: `pending` → `settled` |
| `amount_spent` | numeric (nullable) | المصاريف الفعلية للرحلة |
| `amount_returned` | numeric (nullable) | المبلغ المرجع من السائق |
| `receipts_images` | text[] (default `{}`) | روابط صور الفواتير/الإيصالات |
| `date_return` | text (nullable) | تاريخ العودة/التسوية |
| `created_at` | timestamptz (default now()) | تاريخ الإنشاء |
| `is_deleted` | boolean | للحذف الناعم |
| `treasury_tx_id` | integer (nullable) | FK → treasury_transactions.id (القيد الأساسي) |
| `treasury_tx_extra_id` | integer (nullable) | FK → treasury_transactions.id (قيد إضافي) |

### جدول `treasury_transactions` (الخزينة)
**الملف:** `supabase/migrations/20240101000007_treasury_tva.sql`

| الحقل | النوع | الوصف |
|--------|-------|-------|
| `id` | bigint (identity) | المعرّف الفريد |
| `type` | text | نوع العملية |
| `amount` | numeric (≥ 0) | المبلغ |
| `description` | text | وصف العملية |
| `created_at` | timestamptz (default now()) | تاريخ الإنشاء |

**أنواع `type`:**
- `trip_expense` — مصاريف الرحلات والعُهد (خروج)
- `capital_injection` — تزويد رأس مال (دخول)
- `trip_revenue` — دخل فواتير الرحلات (دخول)
- `owner_withdrawal` — سحب صاحب المشروع (خروج)
- `office_expense` — مصاريف المكتب (خروج)
- `salary` — رواتب الموظفين والسائقين (خروج)

## 2. الطبقة الخدمية (Service Layer)

### دوال العُهد (`supabase_service.dart`)

| الدالة | الوصف |
|--------|-------|
| `getAdvances()` | تجلب العُهد النشطة (`is_deleted` = false/null) مرتبة by `date_out` تنازلياً |
| `getAllAdvances()` | تجلب **جميع** العُهد بما فيها المحذوفة (للأدمن فقط) |
| `addAdvance(data)` | تُنشئ عهدة جديدة |
| `createAdvanceReturning(data)` | تُنشئ عهدة وتُرجع الصف المُنشأ لربطه بأمر رحلة |
| `updateAdvance(id, data, {localRow})` | تُحدّث عهدة مع دعم LWW |
| `deleteAdvance(id)` | حذف ناعم + حذف قيود الخزينة المرتبطة |
| `restoreAdvance(id)` | استرجاع العهدة + إعادة إنشاء قيود الخزينة |
| `syncAdvanceTreasury(advanceId)` | **الغاية الأهم:** يُبقي الخزينة متوافقة مع حالة العهدة |

### دوال الخزينة

| الدالة | الوصف |
|--------|-------|
| `getTreasuryTransactions()` | تجلب جميع حركات الخزينة |
| `addTreasuryTransaction(amount, type, description)` | تسجيل حركة مالية يدوية |
| `getTreasuryBalance()` | تحسب الرصيد الحالي **ديناميكياً** (لا يُخزّن) |
| `getUnifiedLedger({role, period, searchQuery})` | كشف حساب موحد |

## 3. تدفق العمل الكامل (Business Workflow)

### المرحلة 1: إنشاء العهدة (تسليم المال للسائق)

```
┌─────────────────────────────────────────────────────────────────┐
│  السكرتيرة / الأدمن                                              │
│  ┌───────────────────────────────────────────────────────────┐  │
│  │ 1. تفتح شاشة "تسليم عهدة"                                 │  │
│  │ 2. تدخل البيانات:                                         │  │
│  │    - السائق                                               │  │
│  │    - المبلغ الكامل (amount_given)                         │  │
│  │    - تاريخ الانطلاق (date_out)                            │  │
│  │    - الحالة: pending / en_route                           │  │
│  │    - ملاحظات (اختياري)                                    │  │
│  └───────────────────────────────────────────────────────────┘  │
│           ↓                                                     │
│  addAdvance() → جدول advances                                   │
│           ↓                                                     │
│  syncAdvanceTreasury() → يُنشئ قيد في treasury_transactions     │
│    type: 'trip_expense'                                         │
│    amount: amount_given                                         │
│    description: "عهدة السائق [اسم] — تسليم عهدة (#ID)"         │
└─────────────────────────────────────────────────────────────────┘
```

**ملاحظة:** الرصيد يُخصم تلقائياً من الخزينة عند إنشاء العهدة.

---

### المرحلة 2: الرحلة (في الطريق)

```
الحالة: 'pending' أو 'en_route'
- amount_returned = 0
- amount_spent = NULL
- المبلغ الممنوح = amount_given
- القيد في الخزينة: trip_expense = amount_given
```

---

### المرحلة 3: تسوية العهدة (عودة السائق)

```
┌─────────────────────────────────────────────────────────────────┐
│  السكرتيرة                                                      │
│  ┌───────────────────────────────────────────────────────────┐  │
│  │ 1. السائق يسلم البونات والعهدة المتبقية                   │  │
│  │ 2. السكرتيرة تفتح العهدة للتعديل                          │  │
│  │ 3. تدخل:                                                  │  │
│  │    - amount_spent (المصاريف الفعلية)                      │  │
│  │    - date_return (تاريخ العودة)                           │  │
│  │    - amount_returned (يحسب تلقائياً = given - spent)      │  │
│  │    - receipts_images (صور الفواتير/البونات)               │  │
│  └───────────────────────────────────────────────────────────┘  │
│           ↓                                                     │
│  updateAdvance() → status = 'settled'                           │
│           ↓                                                     │
│  syncAdvanceTreasury() → تحديث القيود في الخزينة               │
└─────────────────────────────────────────────────────────────────┘
```

**منطق `syncAdvanceTreasury`:**

| السيناريو | القيد الأساسي | قيد إضافي |
|-----------|---------------|-----------|
| `spent <= given` | يُحدّث إلى `amount = spent` | لا يوجد |
| `spent > given` | يبقى `amount = given` | يُنشأ `amount = spent - given` |

**مثال عملي:**
- العهدة: 2500 درهم
- المصاريف الفعلية: 2100 درهم
- المرجع: 400 درهم (2500 - 2100)
- النتيجة: القيد يُحدّث إلى 2100، والـ 400 المرجع تُضاف تلقائياً للخزينة

---

### المرحلة 4: الحذف والاسترجاع

```
حذف عهدة:
1. يجلب treasury_tx_id و treasury_tx_extra_id
2. يحذف قيود الخزينة المرتبطة (المال يعود للصندوق)
3. يقلب is_deleted = true

استرجاع عهدة:
1. يقلب is_deleted = false
2. يعيد syncAdvanceTreasury() لإنشاء القيود من جديد
```

## 4. سيناريوهات الاستخدام

### السيناريو أ: السكرتيرة تعطي عهدة من الخزينة

```
1. السكرتيرة تفتح "تسليم عهدة"
2. تدخل: السائق + المبلغ + تاريخ الانطلاق
3. يُنشأ قيد: trip_expense (خرج من الخزينة)
4. الرصيد يتحدث تلقائياً
```

### السيناريو ب: الأدمن يعطي عهدة مباشرة للسائق

```
1. الأدمن يفتح "تسليم عهدة" (نفس الشاشة)
2. يدخل البيانات مباشرة
3. يُنشأ قيد: trip_expense (يُخصم من الخزينة)
4. لا حاجة لتدخل السكرتيرة
```

### السيناريو ج: مراقبة الأدمن للخزينة

```
1. الأدمن يفتح "لوحة المالك" أو "شاشة الخزينة"
2. يرى الرصيد الحالي محسوب تلقائياً
3. يرى جميع العُهد (بما فيها المحذوفة)
4. يمكنه تتبع: أين ذهب المال؟ كم بقي في الصندوق؟
```

## 5. كشف الحساب الموحد (Unified Ledger)

**الدالة:** `getUnifiedLedger()` في `supabase_service.dart`

تجمع جميع العمليات في قائمة واحدة:

| المصدر | النوع في الكشف | الوصف |
|--------|---------------|-------|
| treasury_transactions | `treasury` | عمليات الخزينة المباشرة |
| advances (تسليم) | `advance_given` | خروج العهدة للسائق |
| advances (تسوية) | `advance_spent` | صرفيات الرحلة |
| advances (مرجوع) | `advance_returned` | المبلغ المرجع |
| invoices | `invoice` | مداخيل الفواتير |

## 6. القواعد والقيود

| القاعدة | التطبيق |
|---------|---------|
| الرصيد لا يُخزّن | يُحسب ديناميكياً من `treasury_transactions` |
| العهدة تُحذف ناعماً | `is_deleted` = true + حذف قيود الخزينة |
| تراجع الحذف | `restoreAdvance()` يُعيد القيود تلقائياً |
| المرجع التلقائي | `amount_returned = amount_given - amount_spent` |
| LWW للتحديثات | `updateAdvance` يدعم Last-Write-Wins |
| Realtime | الخزينة تستخدم `stream()` لترصد التحديثات فوراً |
| العملة | جميع المبالغ بالدرهم (DH) |

## 7. الشاشات والمسؤوليات

### `advances_screen.dart`
- قائمة العُهد مع فلترة (الكل / معلق / تم التسوية)
- ملخصات: إجمالي المبالغ المعلقة، المبالغ المتبقية
- Dialog لإضافة/تعديل العهدة
- حذف ناعم مع إمكانية التراجع

### `trip_form_screen.dart`
- نموذج سريع لتسليم عهدة مرتبط برحلة
- يُنشئ العهدة ثم يُشغل `syncAdvanceTreasury`
- يُرسل إشعار للأدمن عند الإنشاء

### `treasury_screen.dart`
- إدارة الخزينة المباشرة (إيرادات/مصروفات يدوية)
- Realtime stream لرصد الرصيد الحالي
- أنواع العمليات: تزويد رأس مال، تحصيل فواتير، سحب صاحب المشروع، مصاريف عمومية، رواتب، مصاريف رحلات

### `secretary_ledger_screen.dart`
- كشف حساب موحد لكل العمليات
- فلترة حسب الفترة (يومي/شهري/سنوي)
- يعرض amount_entree و amount_sortie لكل عملية

### `secretary_dashboard_screen.dart`
- ملخص سريع: عدد العملاء، أوامر الرحلات النشطة، الفواتير المتأخرة

## 9. مثال عملي كامل

```
السيناريو: رحلة من الدار البيضاء إلى فرنسا

1. السكرتيرة تعطي عهدة للسائق:
   - amount_given = 2500 DH
   - date_out = 2025-07-15
   - status = pending
   → قيد في الخزينة: trip_expense = 2500 DH (خرج)

2. الرحلة تنطلق...

3. السائق يعود:
   - amount_spent = 2100 DH (مصاريف فعلية)
   - amount_returned = 400 DH (2500 - 2100)
   - date_return = 2025-07-18
   - receipts_images = [صورة البونات]
   → status = settled
   → القيد الأساسي يُحدّث إلى 2100 DH
   → الـ 400 DH المرجع تُضاف تلقائياً للخزينة

4. الرصيد النهائي:
   - الخزينة: دفعت 2500، استرجعت 400 = صافي 2100
   - العهدة: 2500 Given - 400 Returned = 2100 Spent ✓
```

## 10. ملاحظات تقنية

- **العملة:** جميع المبالغ بالدرهم (DH)
- **الرصيد الديناميكي:** لا يُخزّن رصيد ثابت، يُحسب من مجموع الإيرادات - مجموع المصروفات
- **الحذف الناعم:** يسمح بالتراجع واسترجاع البيانات
- **مزامنة الخزينة:** `syncAdvanceTreasury` تُستدعى تلقائياً عند إنشاء/تعديل/استرجاع العهدة
- **الإشعارات:** يُرسل إشعار للأدمن عند إنشاء عهدة جديدة
- **Realtime:** الخزينة تُراقب التحديثات فوراً عبر `stream()`
