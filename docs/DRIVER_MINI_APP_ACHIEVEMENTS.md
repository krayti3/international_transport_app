## 1. Overview

The Driver role has been transformed from a passive read-only view into an active Mini-App.  
Drivers can now see their assigned trip, start/end it, and enable real-time GPS tracking directly from their mobile interface. The secretary receives a notification automatically when a trip is ended, triggering the settlement process. Additionally, drivers are notified locally when a new cash advance is delivered in their name.

### 3.3 New Database Table: `truck_locations`

```sql
CREATE TABLE public.truck_locations (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  truck_id BIGINT NOT NULL REFERENCES public.trucks(id) ON DELETE CASCADE,
  latitude DOUBLE PRECISION NOT NULL,
  longitude DOUBLE PRECISION NOT NULL,
  recorded_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX idx_truck_locations_truck_recorded
  ON public.truck_locations (truck_id, recorded_at DESC);
```

**RLS Policies:**
- Authenticated users can SELECT from `truck_locations`
- Authenticated users can INSERT into `truck_locations`

## 4. Driver Mini-App Behavior

### 4.1 Screen Structure

```dart
DriverScreen (StatefulWidget)
├── AppBar: "رحلاتي" + tracking indicator
└── Body: Column
    ├── [Current Trip Card] — shown only when trip status is `active` or `en_route`
    └── [Upcoming Trips List] — shown when there are future scheduled trips
```

### 4.2 Current Trip Card (Large Card)

- **Header:** Route name + status badge + GPS tracking indicator
- **Details Grid:**
  - Client name
  - Truck plate
  - Direction (outbound/return)
  - Departure date
- **Action Buttons:**
  - **Start Trip** (green): updates status to `en_route` and activates GPS tracking
  - **End Trip** (red): updates status to `completed`, stops GPS, and triggers secretary notification
- **GPS Status Badge:** Shows "تتبع" (tracking) or "جامد" (idle)

### 4.3 GPS Tracking Flow

```dart
// When "Start Trip" is pressed:
1. TripRepository.updateTripStatus(tripId, 'en_route')
2. LocationService.getPositionStream() is subscribed
3. Every position update:
   a. SupabaseService.updateTruckLocation(driverId, lat, lng)
   b. SupabaseService.recordTruckLocation(driverId, lat, lng)
   // => saves to truck_locations table for 24h history
```

### 4.4 Secretary Notification Flow

```dart
// When "End Trip" is pressed:
1. TripRepository.updateTripStatus(tripId, 'completed')
2. _stopGpsTracking()
3. NotificationService.notifySecretaryTripEnded(driverName, route, tripId)
   => Shows local notification: "انتهاء الرحلة - لتسوية العهدة"
```

### 4.5 Cash Advance Notification Flow

```dart
// On driver app open (_loadDriverAndTrips):
1. SupabaseService.getAdvancesByDriver(driverId)
2. If latest advance is new and amount > 0:
   NotificationService.notifyNewAdvanceDelivered(driverName, amount, advanceId)
   => Shows local notification: "عهدة جديدة لديك"
```

### 4.6 Historical Route Polyline (TruckTrackingScreen)

- User taps a truck marker or bottom card
- `_selectedTruckId` is set
- `FutureBuilder<List<LatLng>>` fetches last 24h of `truck_locations`
- `PolylineLayer` renders the route in blue with 4px stroke width

```dart
Future<List<LatLng>> _getPolyline(int truckId) async {
  final history = await supabaseService.getTruckLocationHistory(truckId, hours: 24);
  return history
      .where((p) => p['latitude'] != null && p['longitude'] != null)
      .map((p) => LatLng(p['latitude'], p['longitude']))
      .toList();
}
```

## 7. Error Handling & Edge Cases

- **No driver profile linked to user:** Screen shows empty state with "لا توجد رحلات حالياً"
- **GPS unavailable (Windows):** `LocationService` returns `Stream.empty()`, tracking indicator stays idle
- **Offline mode:** `TripRepository.updateTripStatus` writes directly to Supabase; offline queuing can be added later
- **Duplicate advance notifications:** `_lastNotifiedAdvanceId` prevents re-firing for the same advance record
- **Trip with missing ID:** Start/End buttons are disabled (`onPressed: null`)

## 10. Architecture Decisions

| Decision | Reason |
|----------|--------|
| Use `TripRepository.updateTripStatus` instead of generic `updateTripOrder` | Single-responsibility method; clearer intent |
| Use `LocationService.getPositionStream()` for GPS | Existing service in codebase; handles permissions + platform checks |
| Record GPS to both `trucks.current_latitude/longitude` and `truck_locations` | Real-time location in `trucks` for map markers; historical path in `truck_locations` for Polyline |
| Use local notifications for secretary/advance alerts | Immediate feedback without backend push dependency |
| Exclude advance notification from web builds | `flutter_local_notifications` is mobile-only |
